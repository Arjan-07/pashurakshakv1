# PashuRakshak — Vercel + shared data

## Why the old deployment did not share reports

The original MVP kept `USERS`, `animals`, `reports`, clusters, investigations and samples in Python memory. Vercel can run more than one serverless instance, so PC 1 and PC 2 can hit different instances and see different memory.

This version supports a shared PostgreSQL store. Set the Vercel environment variable `DATABASE_URL` to a hosted PostgreSQL connection string. The app creates the `pashurakshak_state` table automatically on first use.

## Recommended free setup for the hackathon

1. Create a free PostgreSQL database with a provider such as Supabase or Neon.
2. Copy its PostgreSQL connection string.
3. In Vercel, open the project → Settings → Environment Variables.
4. Add:
   - Name: `DATABASE_URL`
   - Value: your PostgreSQL connection string
   - Environments: Production, Preview and Development as needed.
5. Redeploy.
6. Test PC 1: create a farmer, add an animal and submit a report.
7. Test PC 2: log in as the veterinary head and refresh the reports page. The same report should be returned from PostgreSQL.

The database schema is also provided in `database/schema.sql`.

## Roles in this build

- Farmer — OTP login, profile completion, livestock and health reporting.
- Veterinary Head — reviews reports, risk zones, field assessments, lab workflow and assigns tasks to Government Veterinary Interns.
- Government Veterinary Intern — separate dashboard with assigned tasks and surveillance access.
- Field Worker Head — field-focused dashboard, risk zones, visits and assigns tasks to Government Field Interns.
- Government Field Intern — separate dashboard for assigned field tasks and field visits.

## Farmer accounts

Any valid 10-digit Indian mobile number can be used. A phone number can belong to only one account. The OTP is fixed to `123456` for this MVP but is intentionally not displayed in the application UI.

For production, replace the fixed OTP with an SMS/WhatsApp verification provider and add real authentication/authorization.


## Troubleshooting `/api/health`
If `/api/health` returns `status: error`, check Vercel Project Settings > Environment Variables and ensure `DATABASE_URL` is set for Production, then redeploy. Use Supabase Connect > Direct > Transaction pooler > URI. If the database password contains reserved URI characters, use the URI exactly as generated by Supabase (or URL-encode the password). Do not commit the real DATABASE_URL to GitHub.
